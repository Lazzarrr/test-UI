# Moderation Bezvesti — серверный проект

Проект Flask + PostgreSQL для закрытого портала модерации.

## Уже реализовано
- Вход только по выданным учётным данным.
- Роли: Модератор, Старший модератор, Глава модерации.
- Создание аккаунтов Главой и Старшим модератором.
- Ручное задание или автоматическая генерация логина и пароля.
- Хеширование паролей; временный пароль требует смены при первом входе.
- Сброс пароля Главой.
- Дата вступления и назначение ролей изменяются только Главой.
- Устав, отчёты о наказаниях, журнал административных действий.
- CSRF-защита форм, ограничение частоты попыток входа, защитные HTTP-заголовки.

## Важно перед настоящим публичным запуском
Это подготовленный стартовый проект, но не сертифицированный продукт и не прошедший независимый аудит безопасности. Нужны проверка, тестирование и контроль взрослого администратора. Не заносите реальные данные участников до завершения проверки.

## Переменные окружения
- `DATABASE_URL` — строка подключения PostgreSQL.
- `SECRET_KEY` — длинный случайный секрет с панели хостинга.
- `BOOTSTRAP_ADMIN` — имя первого аккаунта Главы.
- `BOOTSTRAP_PASSWORD` — первоначальный пароль Главы (сразу будет требоваться смена).
- `COOKIE_SECURE=1` — только при HTTPS.
- `RATELIMIT_STORAGE_URI` — постоянное хранилище лимитов, например Redis URL; memory:// годится только для локального теста.

## Render
Файл `render.yaml` задаёт веб-сервис и PostgreSQL. Для реального развёртывания выберите оплачиваемые тарифы с постоянной базой данных, проверьте доступность планов и итоговую стоимость в панели Render. Не используйте бесплатную БД для постоянных данных: бесплатный PostgreSQL Render ограничен сроком и не имеет резервных копий.

После создания сервиса:
1. Установите `BOOTSTRAP_ADMIN` и `BOOTSTRAP_PASSWORD` как секретные переменные.
2. Настройте `RATELIMIT_STORAGE_URI` на Redis/совместимое хранилище или выберите иной устойчивый backend для лимитов.
3. Проверьте, что `DATABASE_URL` указывает на PostgreSQL.
4. Убедитесь, что HTTPS включён и `COOKIE_SECURE=1`.
5. Проведите тесты ролей, CSRF, сброса пароля и восстановления базы.

## Локальный запуск
`pip install -r requirements.txt`
`python app.py`
Локально по умолчанию используется SQLite для разработки. Для проверки production-поведения задайте `DATABASE_URL` на тестовую PostgreSQL.
